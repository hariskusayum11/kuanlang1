### ข้อ 2 — Seed สามารถรันซ้ำได้หรือไม่ (Idempotent)?

**✅ ได้ — ทุก Seed ใช้ `upsert` ที่มี `where` เป็น unique key**

| Seed Block | วิธี | Idempotent? |
|---|---|---|
| Province/District/Tambon | `upsert({ where: { code } })` | ✅ |
| Moo | `upsert({ where: { tambonId_number } })` | ✅ |
| Community | `upsert({ where: { code } })` | ✅ |
| Master Data ทั้ง 7 ชุด | `upsert({ where: { code } })` | ✅ |
| RiskWeightConfig | `upsert({ where: { factorCode } })` | ✅ |
| SystemSetting | `upsert({ where: { key } })` | ✅ |

**⚠️ แต่มี 2 ประเด็นสำคัญ:**

1. **`update: {}` ว่างทุกที่** — หมายความว่า **รันซ้ำแล้วไม่อัปเดตอะไรเลย**
   - **ข้อดี:** ไม่ทับค่าที่ Admin แก้ผ่าน UI ✅ (ตั้งใจดี)
   - **ข้อเสีย:** ถ้าแก้ `nameTh` ใน seed.ts แล้วรันใหม่ → **ไม่มีผล** → นักพัฒนาจะงงว่าทำไมแก้ไม่ติด และอาจไปลบ DB ทิ้งแล้วรันใหม่ (ซึ่งอันตรายใน Production)
   - **ข้อเสนอ:** แยกให้ชัดว่าฟิลด์ไหน "Seed เป็นเจ้าของ" (ควร update) กับฟิลด์ไหน "Admin เป็นเจ้าของ" (ห้าม update) — เช่น `nameTh`/`sortOrder` ควร update, `isActive` ไม่ควร

2. **ไม่มีการลบข้อมูลที่ถูกถอดออก** — ถ้าลบ `KL01` ออกจาก array แล้วรัน seed ใหม่ → **`KL01` ยังอยู่ใน DB** → เมื่อเปลี่ยนเป็นชุมชนจริง 5 แห่ง จะได้ **10 ชุมชน** (5 เก่า + 5 ใหม่) → **นี่คือปัญหาที่จะเกิดขึ้นจริงในการแก้ SEED-01** ⚠️

**ระดับ:** 🟡 MEDIUM (SEED-11)

### 🔴 SEED-01 — BLOCKER: ชุมชนทั้ง 5 เป็นข้อมูลสมมติ

**ปัญหา:**

```typescript
// prisma/seed.ts:81-87 — ปัจจุบัน
const communities = [
  { code: "KL01", nameTh: "ชุมชนควนลัง 1", target: 600, tambonId: khuanLang.id },
  { code: "KL02", nameTh: "ชุมชนควนลัง 2", target: 600, tambonId: khuanLang.id },
  { code: "KL03", nameTh: "ชุมชนควนลัง 3", target: 600, tambonId: khuanLang.id },
  { code: "HY01", nameTh: "ชุมชนหาดใหญ่ 1", target: 600, tambonId: hatyaiTambon.id },
  { code: "HY02", nameTh: "ชุมชนหาดใหญ่ 2", target: 600, tambonId: hatyaiTambon.id },
];
```

**ปัญหา 3 ชั้น:**
1. **ชื่อชุมชนไม่มีอยู่จริง** — "ชุมชนควนลัง 1/2/3", "ชุมชนหาดใหญ่ 1/2" เป็นชื่อสมมติ
2. **`target: 600`** — สมมติฐานที่ถูกยกเลิก (CONF-01)
3. **`tambonId` เดี่ยว** — ทำให้ควนสันติ (2 ตำบล) Seed ไม่ได้ (SCH-01)

**ข้อมูลจริงที่ยืนยันแล้ว (จากคำสั่งผู้ใช้):**

| ชุมชน | ตำบล |
|---|---|
| ชุมชนท่าเคียน | ควนลัง |
| ชุมชนประสานมิตร | ควนลัง |
| **ชุมชนควนสันติ** | **ควนลัง + หาดใหญ่** |
| ชุมชนปลักหว้า | ควนลัง |
| ชุมชนหน้าควน | ควนลัง |

**⚠️ ข้อสังเกตสำคัญ:** ข้อมูลจริงมี **4 ชุมชนในตำบลควนลัง + 1 ชุมชนคร่อม 2 ตำบล** — ต่างจาก Seed ที่สมมติว่ามี 3 ชุมชนในควนลัง + 2 ชุมชนในหาดใหญ่ → **ไม่มีชุมชนใดอยู่ในตำบลหาดใหญ่เพียงตำบลเดียว**

**ผลกระทบ:** ถ้ารัน Seed นี้ → ข้อมูลชุมชนผิดทั้งหมด → Batch, Sheet, Household ทั้งหมดจะผูกกับชุมชนที่ไม่มีอยู่จริง → **ต้องล้างข้อมูลใหม่ทั้งหมด**

**แนวทางแก้ไข:** ดู [15-database-fix-plan.md](15-database-fix-plan.md) FIX-16 + [05-community-area-design.md](05-community-area-design.md) หัวข้อ 4.4

**ต้องใช้ข้อมูลเพิ่มเติม:** รหัสชุมชนที่จะใช้ (Q-21), ตำบลหลักของควนสันติ (Q-17), `totalHouseholds` จริง (Q-01)

**Module ที่กระทบ:** M04, M02, M11, M10, ทุก Module ที่อ้างชุมชน

### 🟠 SEED-03 — HIGH: รหัสอำเภอหาดใหญ่ "9001" น่าจะผิด

**ปัญหา:**

```typescript
// prisma/seed.ts:22-31
const hatyai = await prisma.district.upsert({
  where: { code: "9001" },       // ⚠️ ต้องตรวจสอบ
  create: { code: "9001", nameTh: "หาดใหญ่", ... },
});
```

**ข้อสังเกต:** ตามระบบรหัสพื้นที่มาตรฐานของกรมการปกครอง (ที่ใช้รูปแบบ `จังหวัด 2 หลัก + อำเภอ 2 หลัก`) รหัส **`9001` โดยทั่วไปหมายถึง "อำเภอเมืองสงขลา"** ซึ่งเป็นอำเภอลำดับที่ 1 ของจังหวัด ส่วน **อำเภอหาดใหญ่มักใช้รหัส `9011`**

เช่นเดียวกัน รหัสตำบลที่ใช้ (`900105` = ควนลัง, `900101` = หาดใหญ่) เป็นการต่อยอดจากรหัสอำเภอ `9001` → **ถ้ารหัสอำเภอผิด รหัสตำบลก็ผิดตามทั้งหมด** (ควรเป็น `9011xx`)

**⚠️ หมายเหตุสำคัญ:** ตามคำสั่งผู้ใช้ *"อย่าเดาข้อมูลพื้นที่"* → เอกสารนี้**ไม่ยืนยัน**ว่ารหัสที่ถูกต้องคืออะไร แต่**ชี้ว่ารหัสปัจจุบันมีความเสี่ยงสูงที่จะผิด** และต้องตรวจสอบกับแหล่งข้อมูลทางการก่อนใช้

**ผลกระทบ:**
- **`code` เป็น `@unique`** และเป็นตัวเชื่อมกับระบบราชการ → ถ้าผิดจะเชื่อมข้อมูลกับหน่วยงานอื่นไม่ได้ (KPI: "จำนวนหน่วยงานที่ใช้ร่วมกัน ≥ 3")
- Seed ใช้ `upsert({ where: { code } })` → **ถ้าแก้รหัสภายหลัง จะสร้างแถวใหม่แทนที่จะอัปเดต** → ได้อำเภอ 2 แถว (9001 + 9011)
- กระทบการขยายพื้นที่ (ถ้าเพิ่มอำเภอเมืองสงขลาจริงในอนาคต → รหัส 9001 ชนกัน)

**แนวทางแก้ไข:**
1. **ตรวจสอบรหัสกับแหล่งข้อมูลทางการ** — กรมการปกครอง / ระบบ TIS-1099 / ข้อมูลเทศบาลนครหาดใหญ่
2. พิจารณาใช้ **Dataset รหัสพื้นที่ไทยมาตรฐาน** (มีเผยแพร่เป็น Open Data) แทนการพิมพ์เอง → ลดความเสี่ยงและรองรับการขยายทั่วประเทศตาม CLAUDE.md
3. เพิ่ม Validation ว่า `Tambon.code` ต้องขึ้นต้นด้วย `District.code` และ `District.code` ต้องขึ้นต้นด้วย `Province.code`

**ต้องใช้ข้อมูลเพิ่มเติม:** รหัสอำเภอ/ตำบลที่ถูกต้อง (ดู Q-24)

**Module ที่กระทบ:** M04, M11, M16

| **`HAT_YAI_LNG_MIN/MAX`** | 100.3 / 100.7 | 🔴 **ไม่ควรอยู่ที่นี่** | เหตุผลเดียวกัน |

**สิ่งที่ควรอยู่ใน Config (`.env`) ไม่ใช่ DB:**
- `DATABASE_URL`, `BETTER_AUTH_SECRET`, `ENCRYPTION_KEY`, `REDIS_URL`, `S3_ENDPOINT`, `GOOGLE_MAPS_API_KEY` → ✅ **ปัจจุบันไม่มีใน Seed ถูกต้องแล้ว**

**หลักการที่เสนอ:**

| ประเภท | อยู่ที่ | ตัวอย่าง |
|---|---|---|
| **Secret** | `.env` (ห้าม Commit ตาม CLAUDE.md) | Key, Password, Token |
| **Infrastructure Config** | `.env` | URL, Port, Endpoint |
| **นโยบายที่ Admin ปรับได้** | `SystemSetting` (DB) | Lock timeout, Retention |
| **ข้อมูลพื้นที่** | ตารางพื้นที่ (Province/Community) | Bounding Box, ขอบเขต |
| **Master Data** | ตาราง Master Data | ประเภทต่างๆ |

**⚠️ ปัญหาเพิ่มเติมของ `SystemSetting`:**
- **`value Json` ไม่มี Type Safety** — `LOCK_TIMEOUT_MINUTES` อาจถูกตั้งเป็น `"สิบ"` (string) แล้วโค้ดพัง runtime → ควรมี `valueType` + Zod Schema ต่อ Key
- **ไม่มี Validation** — ตั้ง `LOCK_TIMEOUT_MINUTES = -5` ได้
- **ไม่มี Audit** — `updatedBy` เป็น String เปล่าไม่มี FK และไม่มีประวัติการเปลี่ยน

**ระดับ:** 🟡 MEDIUM (SEED-07)
