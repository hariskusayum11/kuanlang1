# 30 — ธงเปิด/ปิดระบบอีเมล และรหัสผ่านชั่วคราว

**Owner Decision 2026-10-17** · สถานะ: **บังคับใช้แล้ว** · บนระบบจริงตั้งเป็น `EMAIL_ENABLED=false`

---

## 1. ที่มา

บัญชี Gmail ที่ระบบใช้ส่งอีเมล (`sklfris.notification@gmail.com`) ถูก Google **ปิดถาวร**
เมื่อ 5 ก.ย. 2569 โดยระบุว่าน่าจะเป็นบัญชีที่สร้างด้วยโปรแกรมอัตโนมัติ ผลคือ App Password
ถูกเพิกถอน และสร้างใหม่ไม่ได้ตราบใดที่บัญชียังถูกปิด

ทางแก้ที่ถูกต้องระยะยาวคือใช้บริการส่งอีเมลสำหรับระบบ (transactional email) พร้อมผูกโดเมน
`khuanlangmodel.com` เพื่อให้ผ่าน SPF/DKIM — แต่**โครงการยังไม่มีสิทธิ์จัดการ DNS ของโดเมน**
(ผู้ดูแลโดเมนคืออาจารย์ผู้ควบคุมโครงการ)

**จึงตัดสินใจ "ปิด" ไม่ใช่ "ลบ"** — เพื่อให้เปิดกลับได้ด้วยการแก้ env บรรทัดเดียวเมื่อ DNS พร้อม
โดยไม่ต้องเขียนโค้ดใหม่ (แนวทางเดียวกับ Double-Entry และ Batch ที่คงไว้ในสคีมาแต่ปิดใช้งาน)

## 2. ระบบใช้อีเมลทำอะไรบ้าง (ทั้งหมดมีแค่ 2 อย่าง)

| # | ใช้ตอนไหน | ที่อยู่จริง | ถ้าไม่ถึงปลายทาง |
|---|---|---|---|
| 1 | ยืนยันอีเมลตอนสมัคร (ลิงก์อายุ 24 ชม.) | `lib/auth.ts` → `emailVerification.sendVerificationEmail` | ADMIN กดอนุมัติไม่ได้ → คนใหม่เข้าระบบไม่ได้ |
| 2 | ลืมรหัสผ่าน (ลิงก์อายุ 30 นาที) | `lib/auth.ts` → `emailAndPassword.sendResetPassword` | ผู้ใช้ถูกล็อกออกถาวร (รหัสถูก hash แก้ใน DB ตรง ๆ ไม่ได้) |

ไม่มีเมลแจ้งเตือน ไม่มีส่งรายงาน ไม่มีเมลเตือนภัย

## 3. พฤติกรรมเมื่อ `EMAIL_ENABLED=false`

| ส่วน | พฤติกรรม |
|---|---|
| `sendSystemEmail` | คืนค่าทันทีโดยไม่เรียก SMTP (ด่านสุดท้ายกันเรียกหลุด) |
| สมัครสมาชิก | ไม่ส่งลิงก์ยืนยัน · คำขอยังถูกสร้างครบ · ข้อความบนหน้าจอเปลี่ยนเป็น "ผู้ดูแลระบบจะติดต่อกลับ" |
| อนุมัติคำขอ | **ไม่บังคับ `emailVerified`** — ไม่งั้นจะอนุมัติใครไม่ได้เลยทั้งระบบ |
| `/forgot-password`, `/verify-email` | แสดงคำอธิบายทางออกที่ใช้ได้จริง แทนฟอร์มที่กดแล้วไม่เกิดอะไร |
| หน้าเข้าสู่ระบบ | ซ่อนลิงก์ "ลืมรหัสผ่าน?" → แสดง "ติดต่อผู้ดูแลระบบ" |
| `/admin/registrations` | ซ่อนป้าย "ยังไม่ยืนยันอีเมล" (กลายเป็นคำเตือนที่ไม่มีใครทำอะไรได้) |

### ด่านความปลอดภัยที่ "ไม่" ถูกลดลง

ด่านกันคนนอกตัวจริงของระบบคือ **ADMIN อนุมัติ** ไม่ใช่การยืนยันอีเมล — บัญชีใหม่ทุกบัญชี
เกิดมาเป็น `isActive=false` (บังคับใน `user.create.before` hook) จึง login ไม่ได้และไม่มีสิทธิ์ใด
จนกว่าจะได้รับอนุมัติ การปิดอีเมลจึงถอด**ด่านรอง**ออกเท่านั้น

ความเสี่ยงที่รับไว้: ไม่มีใครตรวจว่าอีเมลที่กรอกสะกดถูก — ADMIN ต้องทวนอีเมลกับเจ้าตัวตอนอนุมัติ

## 4. รหัสผ่านชั่วคราว (ของทดแทน "ลืมรหัสผ่าน")

**ไม่มีสิ่งนี้ = ปิดอีเมลไม่ได้** เพราะผู้ใช้ที่ลืมรหัสจะถูกล็อกออกถาวร

เส้นทางปกติ — ADMIN กด **"ตั้งรหัสใหม่"** ในหน้า `/admin/users`:

1. ระบบ**สุ่ม**รหัสให้เสมอ (ADMIN ตั้งเองไม่ได้ — กันรหัสเดาง่าย/ซ้ำกับระบบอื่นของผู้ใช้)
2. แสดงรหัสบนหน้าจอ **ครั้งเดียว** — ไม่เก็บลง DB ไม่เขียนลง log
3. ตั้ง `User.mustChangePassword = true` → ผู้ใช้ถูกบังคับเปลี่ยนรหัสก่อนใช้งานหน้าอื่น
4. ลบ session ทั้งหมดของผู้ใช้ → อุปกรณ์ที่ค้างอยู่ถูกตัดทันที
5. เขียน Audit Log (`UserCredential` / `admin-temp-password`) โดยไม่มีค่ารหัสผ่าน

**กู้ฉุกเฉิน** — เมื่อ ADMIN คนเดียวของระบบลืมรหัสตัวเอง จึงไม่มีใครเข้าหน้าจัดการผู้ใช้ได้:

```bash
docker compose exec app npm run password:reset -- someone@example.com
```

### ทำไมต้องบังคับเปลี่ยนรหัส

รหัสชั่วคราวเดินทางผ่านช่องทางนอกระบบ (โทรศัพท์/ไลน์) และ**มีคนอื่นรู้ค่า** —
ถ้าปล่อยให้ใช้ต่อได้เรื่อย ๆ จะกลายเป็นรหัสถาวรที่ผู้อื่นรู้ สำหรับระบบที่เก็บข้อมูลสุขภาพ
และกลุ่มเปราะบาง นี่เป็นความเสี่ยงที่รับไม่ได้

หน้ากั้นอยู่ที่ `app/(dashboard)/layout.tsx` — **เรนเดอร์ทับ ไม่ใช่ redirect** เพราะหน้าโปรไฟล์
อยู่ใน route group เดียวกัน การ redirect จะวิ่งกลับเข้า layout เดิมซ้ำไม่รู้จบ

## 6. วิธีเปิดอีเมลกลับ (เมื่อ DNS พร้อม)

1. ผูกโดเมนกับผู้ให้บริการส่งอีเมล (เพิ่ม SPF/DKIM ที่ DNS ของ `khuanlangmodel.com`)
2. ตั้ง `SMTP_*` ใน `.env` ให้ครบและทดสอบด้วย `transporter.verify()`
3. เปลี่ยน `EMAIL_ENABLED=true`
4. `docker compose up -d` (compose ต้องส่ง `EMAIL_ENABLED` เข้า service `app`)

ไม่ต้องแก้โค้ดใด ๆ · ผู้ใช้เดิมที่ `emailVerified=false` ยังใช้งานได้ตามปกติ เพราะถูกอนุมัติ
ด้วย ADMIN ไปแล้ว — ด่านยืนยันอีเมลมีผลกับ**คำขอที่ยังไม่ถูกอนุมัติ**เท่านั้น

> ⚠️ ถ้าเปิดกลับแล้วมีคำขอ PENDING ค้างอยู่ คำขอเหล่านั้นจะอนุมัติไม่ได้จนกว่าผู้สมัคร
> จะยืนยันอีเมล — ให้ผู้สมัครไปที่ `/verify-email` เพื่อขอลิงก์ใหม่
