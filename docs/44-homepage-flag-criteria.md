# 44 — หน้าแรก "สองคลอง" · เกณฑ์ธงเตือนภัยแก้ได้ในระบบ · ยืนยันก่อนโทร

**Owner Decision 2026-11-09** · สถานะ: **บังคับใช้แล้ว**

## 1. หน้าแรกใหม่
- `/` คือหน้า "สองคลอง" (เดิมเป็นต้นแบบที่ `/lab/song-khlong` — ลิงก์เดิมพามาหน้าแรก)
- เนื้อหา: ธงเตือนภัยโดยประมาณ + ฉากระดับน้ำเทียบตลิ่ง/เส้นธง + ย้อนดูน้ำท่วม พ.ย. 68 + พยากรณ์ฝน + การ์ดอากาศ ·
  เบอร์ฉุกเฉิน · เกณฑ์ธงรายสะพาน · แผนที่ (จุดวัดน้ำ/ฝน · ความรุนแรงน้ำท่วม ตาม docs/39) · เตรียมพร้อม · ร่วมเครือข่าย · ที่มาของข้อมูล
- **ข้อมูล ThaiWater:** เจ้าของระบบอนุญาตให้ใช้บนหน้าแรกได้ เพราะผู้บริหารยื่นหนังสือขออนุญาตต่อ สสน. แล้ว
  (ร่างหนังสืออยู่ที่เจ้าของระบบ) · ต้องคงเครดิต "คลังข้อมูลน้ำแห่งชาติ (สสน.) · สถานีกรมชลประทาน" ทุกจุดที่แสดงค่า ·
  เมื่อ สสน. ตอบกลับ ให้บันทึกเลขที่หนังสืออนุญาตในส่วนที่มาของข้อมูล และปรับตามเงื่อนไขที่ได้รับ
- ความเป็นส่วนตัวเหมือนเดิม: ไม่มีชื่อ เบอร์ บ้านเลขที่ หรือพิกัดรายบ้าน · แผนที่ความรุนแรงเป็นช่อง ~200 ม. ≥ 5 หลัง

## 2. เกณฑ์ธงเตือนภัยแก้ได้ในระบบ
หน้า **`/flag-criteria`** (เมนู "เกณฑ์ธงเตือนภัย" หมวดระบบ) — ADMIN เท่านั้น

| แก้อะไรได้ | รายละเอียด |
| --- | --- |
| ระดับธง | เพิ่ม/ลบ/เรียง (ระดับปกติอยู่บนสุดเสมอ) · ชื่อธง · สี (เขียว/เหลือง/ส้ม/แดง) · ไซเรน · สถานการณ์ · ข้อความบนหน้าแรก · สิ่งที่ต้องทำ |
| เกณฑ์รายสะพาน | ต่อระดับ: ไม่ใช้ / ต่ำกว่าท้องสะพาน x ม. / น้ำถึงพื้นสะพาน / ระดับน้ำ x ม.รทก. — เห็นค่า ม.รทก. และระยะถึงระดับน้ำตอนนี้ทันที |
| สะพาน | ชื่อ · ลำน้ำ · รหัสสถานี ThaiWater · **ระดับท้องสะพาน (พื้นล่างสะพาน)** · ระดับพื้นสะพาน · ที่มา · เพิ่ม/ลบสะพาน |
| ที่มาของเกณฑ์ | ผู้กำหนด · ลิงก์ · สัญญาอนุญาต · หมายเหตุ |

กติกา:
- **ไม่เขียนทับ** — ทุกการบันทึกเป็นฉบับใหม่ (`flag_criteria_version`) พร้อมเหตุผล ผู้แก้ เวลา และ Audit Log รายการที่เปลี่ยน
  · มีคนบันทึกระหว่างที่หน้าเปิดอยู่ → `CONFLICT` ให้โหลดใหม่ · "นำค่าฉบับนี้มาแก้" จากประวัติเพื่อย้อนกลับ (บันทึกเป็นฉบับใหม่)
- ตรวจที่ server ทุกครั้ง: สิทธิ์ `flag-criteria.manage` · Zod · `validateFlagCriteria` (เกณฑ์ระดับสูงต้องสูงกว่าระดับต่ำ ·
  เกณฑ์ที่อ้างท้องสะพาน/พื้นสะพานต้องมีค่านั้น · พื้นสะพานไม่ต่ำกว่าท้องสะพาน · รหัสไม่ซ้ำ)
- ยังไม่มีฉบับในฐานข้อมูล หรือฉบับล่าสุดอ่านไม่ได้ → ใช้ `DEFAULT_FLAG_CRITERIA` ในโค้ด (หน้าแรกต้องแสดงได้เสมอ)
- ธงของกลุ่ม = ธงสูงสุดของทุกสะพาน · สะพานที่ไม่มีข้อมูลไม่นับ · ไม่มีข้อมูลเลย = "ไม่ทราบ"
- สะพานที่เพิ่มใหม่: หน้าแรกดึงระดับน้ำของสถานีนั้นจาก ThaiWater ให้อัตโนมัติ (รหัสต้องตรงกับ ThaiWater)
- ธงบนหน้าแรกยังเป็น **การประเมินของระบบ ไม่ใช่ธงที่กลุ่มประกาศ** — บอกไว้ทุกจุดที่แสดง

## 4. ความเร็วของข้อมูลระดับน้ำ (2026-11-09)
- สถานีโทรมาตรกรมชลประทาน (X.174 X.173A X.90 X.44) **ส่งค่าชั่วโมงละ 1 ครั้ง** (ตรงชั่วโมง) — เป็นขีดจำกัดของต้นทาง
- รายการ "ล่าสุด" ของ ThaiWater (`waterlevel_load`) ช้ากว่ากราฟรายชั่วโมง (`waterlevel_graph`) ราว 30 นาที —
  หน้าแรกจึงใช้ค่าชั่วโมงล่าสุดจากกราฟเมื่อใหม่กว่า (`freshenReadings` · ค่าชั่วโมงเดียวกันตรงกันทั้งสองแหล่ง)
- แคชฝั่ง server: ระดับน้ำ 2 นาที · จุดวัดฝน 5 นาที · ข้อมูลน้ำท่วม พ.ย. 68 1 วัน
- หน้าที่เปิดค้างไว้ดึงข้อมูลใหม่เองทุก 2 นาที (เฉพาะตอนแท็บแสดงอยู่) และทันทีเมื่อกลับมาที่แท็บ — `components/ui/auto-refresh.tsx`
- ผลรวม: ค่าชั่วโมงใหม่ขึ้นบนหน้าแรกภายในไม่กี่นาทีหลังสถานีส่งเข้าคลังข้อมูลน้ำแห่งชาติ
